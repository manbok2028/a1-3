# 체납리셋 서비스 기획서

> 구현 구조의 선택 이유, 실제 세무사 연결 시의 API·데이터 경계는 [배포·보안·API 운영 기록](deployment-security-and-api.md)의 **구조 선택·확장 설계**에서 확인할 수 있습니다.

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 체납리셋 |
| 목적 | 체납자가 자신의 상황을 이해하고, 공식 기관 확인과 전문가 상담 준비를 위한 다음 행동을 정리하도록 돕는다. |
| 타겟 사용자 | 세무 지식이 부족한 개인 체납자, 자영업자·프리랜서·폐업 경험자 |
| 제공 가치 | 어려운 체납 관련 정보를 쉬운 언어의 요약·체크리스트·상담 준비 태그로 바꾼다. |
| 서비스 경계 | 세무·법률 자문, 제도 적용 판단, 세무대리, 수수료 기반 알선을 제공하지 않는다. |

## 2. 페이지 구성과 이동

| 페이지 | 주소 | 역할 | 이동 |
|---|---|---|---|
| 메인 | `index.html` | 서비스 소개와 AI 진단 CTA | 상단 메뉴·CTA |
| AI 상황 정리 | `diagnosis.html` | 입력폼, AI 결과, 매칭 태그 | 상단 메뉴·결과 CTA |
| 제도 안내 | `guide.html` | 분할 납부·유예 관련 확인 방향과 공식 링크 | 상단 메뉴 |
| 세무사 연결 | `connect.html` | 가상 프로필 태그 필터와 상담 준비 UX | 결과 CTA·상단 메뉴 |
| FAQ·문의 | `contact.html` | 개인정보·서비스 한계·기관 확인 안내 | 상단 메뉴 |

## 3. AI 기능 설계

| 구분 | 내용 |
|---|---|
| 입력 | 세목 구분, 대략적 체납액, 체납 기간, 현재 상황, 300자 이내 추가 설명 |
| 처리 | 프론트가 JSON `POST /api/diagnose` 요청 → Python이 검증 → OpenAI API가 구조화된 JSON 반환 |
| 출력 | 상황 요약, 확인해 볼 제도·상담 방향, 다음 행동 체크리스트, 매칭 태그 |
| 사용자 가치 | 통지서와 현재 사정을 정리해 관할 기관 문의 또는 전문가 상담 전 준비 시간을 줄인다. |
| 안전 제한 | 정확한 가산금 계산·신청 가능 여부·처분 결과를 단정하지 않고 고지 문구를 항상 붙인다. |

## 4. 실패 처리 기준

| 상황 | 화면 동작 | API 동작 |
|---|---|---|
| 필수 입력 누락 | 즉시 “필수 항목을 입력해 주세요” 표시 | 호출하지 않음 |
| 금액 오류 | 0보다 큰 숫자를 요청 | 호출하지 않음 |
| API 401/403/429/5xx | 인증·한도·일시 오류 안내 | `503`과 안전한 오류 메시지 반환 |
| 15초 지연 | 지연 안내와 재시도 권고 | `AbortController`로 프론트 요청 중단 |
| 모델 응답 형식 오류 | 다시 시도 안내 | 백엔드에서 구조 검증 후 오류 반환 |

## 5. 세무사 연결 확장 원칙

현재는 `data/tax-accountants.json`의 **가상 프로필**만 태그로 필터링한다. 실제 운영 전에는 세무사 자격·정보 정확성, 개인정보 처리, 상담 계약, 소개·알선 및 수수료 관련 법적 검토가 필요하다. 사용자의 진단 입력과 연락처를 외부로 자동 전송하지 않으며, 실제 계약·수임 여부는 사용자와 세무 전문가가 직접 협의한다.

## 6. 반응형·보너스 설계

- 1440px 데스크톱에서는 2~3열 카드 레이아웃을 사용한다.
- 375px 모바일에서는 메뉴·폼·카드를 1열로 쌓는다.
- 다크 모드 토글을 제공하고 선택값을 `localStorage`에 저장한다.
- 태그 기반 프로필 필터와 상담 준비 완료 메시지로 마이크로 인터랙션을 제공한다.
